# Bubble Breaker｜陌生输入与信息茧房探索
## 目标
帮助用户持续接触"世界本身"，而不只是继续消费熟悉的知识型、自我成长型内容。
这个 Skill 最重要的闭环不是"推荐更多东西"，而是：
```text
发现一个陌生但高质量的资源
→ 生成一个待完成的阅读 / 收听 / 观看任务
→ 用户认真完成
→ 只记录完成事实与时间
→ 下一次继续向不同方向探索
```
默认不要求用户总结观点、写心得、提炼行动或证明"学到了什么"。
一次只推进一个资源。
## 开始前读取
- 根目录 `README.md`（如有）；
- 用户指定的话题、资源或日期范围；
- 运行 `discover` 时，按需读取最近少量相关 `daily/inputs/`，避免重复推荐已经完成过的资源或持续停留在同一种领域；
- 只有任务需要时，才读取少量 `daily/journal/` 或 Practice 材料。
不要为了"个性化"穷举个人历史。
## 核心原则
- **世界输入优先**：优先真实世界、具体对象、第一手材料、长期观察、调查、纪录和专业实践。
- **异质性优先**：不是简单把中文换成英文，而是改变领域、生产者、形式和问题意识。
- **一次一个**：每次只推荐一个具体资源，不给十几个收藏链接。
- **完成优先收藏**：目标是认真读完、听完或看完，而不是扩大待读列表。
- **不强迫意义**：资源可以暂时和用户生活没有明确关系。
- **不强迫输出**：完成后默认只记录"我在什么时候接触了什么"。
- **诚实优先**：不编造标题、作者、集数、链接、发布时间或可访问性；推荐前必须核实。
- **深度优先宽度**：宁可一个真正值得花时间的资源，也不要浅薄多样化。
## 资源探索范围
优先探索用户当前 feed 中相对稀缺的领域：
- 自然科学、生态、动物、植物、地质、海洋、天文；
- 城市、建筑、基础设施、交通、公共空间；
- 调查报道、社会现场、纪实写作；
- 历史、考古、人类学、语言；
- 艺术、设计、音乐、电影制作、博物馆；
- 工程、制造、农业、能源、物流和普通职业世界；
- 法律、制度、公共政策的具体案例；
- 其他真实、具体、目前很少进入用户 feed 的领域。
默认降低以下内容的优先级：
- self-help；
- 个人成长；
- 效率与生产力；
- 泛心理学；
- "如何过好人生"式观点内容；
- 只是在解读另一本书或总结另一个人的二手知识；
- 与近期连续推荐高度相似的主题。
不是永远禁止这些领域，而是 `discover` 默认负责扩大输入物种。
## 语言与形式
- 中文与英文都可以；长期看尽量形成语言上的多样性，但不机械 1:1 轮换；
- 语言多样性低于领域和内容生产方式的多样性；
- 可以是：文章、长篇报道、播客单集、纪录片、高质量视频、公开讲座、书或书中明确可完成的一部分；
- 优先推荐一次可以完整完成的具体单元，而不是只推荐一个平台、频道或模糊书单。

# 核心模式
## 1. `discover`｜发现一个陌生输入任务
触发：
```text
/bubble-breaker discover
/bubble-breaker discover [可选方向]
```
定时任务默认使用这个模式。
### 流程
1. 读取本 Skill；
2. 必要时查看近期少量完成记录，避免重复资源和连续同类领域；
3. 在公开网络中搜索候选资源；
4. 核实资源真实存在、标题/作者或节目名正确、链接可访问，并尽量确认长度或所需时间；
5. 在候选里选择 **1 个**，优先满足：
   - 与用户现有 feed 有明显距离；
   - 本身有高质量证据、叙事、观察或专业内容；
   - 值得认真花一段时间，而不是只提供一个"有趣事实"；
   - 能作为某个陌生领域的具体入口；
6. 输出一个待完成任务，不写入 `daily/inputs`；
7. 等用户真正完成后，再进入 `complete`。
### 推荐时的输出格式
```md
## 今日陌生输入
**任务**：认真读完 / 听完 / 看完《{title}》
- 来源：{creator / publication / podcast / channel}
- 类型：{article / podcast / documentary / video / book}
- 预计时间：{only if verified or reasonably available}
- 链接：{verified URL}
**为什么选它**
{2–4 句，说明它和近期常见输入哪里不同，以及它打开了哪一扇新窗口。}
完成后只需要告诉我：**"完成了"**。
不要求写心得；有想法时再记录想法。
```
### 不要做的事
- 不在推荐时自动创建 Daily 笔记；
- 不因为推荐了资源就假装用户已经阅读；
- 不附带 5 个"顺便可以看看"；
- 不要求用户带着问题阅读；
- 不强行告诉用户这个资源"会改变你的人生"；
- 不把每个资源都转译成个人成长启示。

## 2. `complete`｜记录已完成的陌生输入
触发：
```text
/bubble-breaker complete
/bubble-breaker complete [resource]
```
也适用于用户在收到推荐后说：
```text
完成了
读完了
听完了
看完了
```
### 流程
1. 确认当前会话中最近一个明确的陌生输入资源；
2. 如果当前上下文无法确定资源，再查看近期 `daily/inputs` 或让用户提供资源名；不要猜；
3. 优先使用 `PROFILE.md` 中的时区记录实际完成日期和时间；未填写时使用当前执行环境的本地时区，若日期有歧义再询问；
4. 按 `capture-input` 规范写入：
```text
daily/inputs/{YYYY}/{YYYYMM}/{YYYYMMDD}-{keyword}.md
```
5. 默认只记录完成事实，不生成总结；
6. 如果用户主动说了感受、观察或连接，再把这些真实内容追加进去，不替用户补心得。
### 极简完成记录模板
```md
---
title: "{resource title}"
date: {YYYY-MM-DD}
source: "{creator / publication / podcast / channel if known}"
tags:
  - input
  - bubble-breaker
---
## 完成记录
- 内容：{resource title}
- 类型：{article / podcast / documentary / video / book}
- 完成时间：{YYYY-MM-DD HH:mm}
- 链接：{verified URL if available}
这次只记录完成事实，不要求总结。
```
如果用户主动提供了想法，可以追加：
```md
## 我留下来的东西
{只整理用户真实表达，不替用户制造观点。}
```
### 去重规则
- 同一个资源已经有完成记录时，不新建重复文件；
- 用户是在第二次阅读/收听时，可在原文件追加新的 `再次完成时间`；
- 同日文件名冲突时，按 `capture-input` 规范具体化关键词；
- 不创建 `v2`、`final`。

## 参数解析
- 第一个 token 匹配 `discover` 或 `complete` 时，使用对应模式；
- 没有参数时：
  - 在定时探索或用户要求"给我一个陌生输入"语境下默认 `discover`；
  - 在用户表达刚完成推荐资源时默认 `complete`；
  - 其他情况下默认 `discover`；
- 参数是仓库相对文件路径时，读取该文件作为主要输入；
- 不接受或记录本机绝对路径作为长期来源。

## 飞书 Drive 上传执行（重要）
在豆包/AI 环境中，本地文件系统是**临时的**，写入本地文件后**必须上传到飞书 Drive** 才是持久存储。绝不能只创建本地文件就结束任务。
执行步骤（`complete` 模式）：
1. **在本地工作目录创建 md 文件**，使用相对路径（如 `./{YYYYMMDD}-{关键词}.md`）。
2. **定位或创建年月分层目录（必须，先查后建）**：飞书 Drive 路径必须为 `daily > inputs > {YYYY} > {YYYYMM}`。

   > **⚠️ 关键警告**：飞书 Drive 允许同名文件夹并存。每一层都必须先列出父目录下的子项，精确匹配名称；存在则复用 token，不存在才创建。

   先定位 `inputs`。搜索到多个同名结果时，只选择目标 `daily` 下的目录；无法确定时让用户确认：

   ```bash
   lark-cli drive +search --query "inputs" --doc-types folder --format json
   ```

   再完整列出 `inputs` 子项，精确匹配 `type == "folder"` 且 `name == "{YYYY}"`：

   ```bash
   lark-cli drive files list --params '{"folder_token":"{inputs文件夹token}","page_size":200}' --format json
   ```

   找到 1 个则复用，找到多个则停止创建并消歧。只有找到 0 个时才执行：

   ```bash
   lark-cli drive +create-folder --name "{YYYY}" --folder-token "{inputs文件夹token}"
   ```

   然后完整列出年份文件夹子项，精确匹配 `type == "folder"` 且 `name == "{YYYYMM}"`：

   ```bash
   lark-cli drive files list --params '{"folder_token":"{年份文件夹token}","page_size":200}' --format json
   ```

   同样，找到 1 个则复用，找到多个则停止创建并消歧。只有找到 0 个时才执行：

   ```bash
   lark-cli drive +create-folder --name "{YYYYMM}" --folder-token "{年份文件夹token}"
   ```

   两次列表响应若还有下一页，都必须继续分页直到列完，再判断匹配数量。

   **必须按年月分层组织，不要直接上传到 inputs 根目录。** 即使当前 inputs 下是扁平结构，新文件也必须进入年月子目录，逐步完成迁移。
3. **上传到对应年月文件夹**：
   ```bash
   lark-cli drive +upload --file ./{YYYYMMDD}-{关键词}.md --folder-token "{年月文件夹token}"
   ```
4. **记录返回的 file_token 和 url**。后续更新同一文件时，使用 `--file-token` 覆盖上传，保留原文件链接。
注意：`--file` 必须使用**相对路径**，不能用绝对路径，否则会报 `unsafe file path` 错误。
## 完成检查
### discover
- 是否只推荐了 1 个具体资源？
- 是否核实了标题、来源和链接？
- 是否真的比近期 feed 更异质，而不是换语言重复同类内容？
- 是否避免近期重复领域和重复资源？
- 是否没有提前写入 Daily？
- 是否明确告诉用户完成后只需说"完成了"？
### complete
- 用户是否真的明确表示完成？
- 是否记录了实际完成时间？
- 是否按 `PROFILE.md` 中的时区记录，或在日期有歧义时询问？
- 是否只记录真实存在的资源信息？
- 是否没有强迫总结、行动化或人生启示？
- 用户若表达了感受，是否只整理真实表达？
## 完成后的回复
### discover
只返回待完成任务本身和极简说明，不额外堆推荐。
### complete
简短说明：
1. 已记录完成；
2. 写入或更新的相对路径；
3. 若用户没有提供心得，明确本次只记录完成事实即可。
